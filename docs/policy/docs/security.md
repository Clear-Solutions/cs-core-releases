# Безопасность проектов и репозиториев

Секреты хранятся в GitHub environment secrets или менеджере секретов. `.env`, приватные ключи, дампы БД, реальные загруженные файлы и production-логи не попадают в Git, контекст агента и artifacts. `.env.example` содержит только имена и безопасные заглушки. Компрометированный секрет отзывают; простое удаление файла из истории не решает утечку.

GitHub Actions используют `permissions: contents: read` по умолчанию, ограниченные permissions в конкретном job, проверенные actions по полному SHA и `persist-credentials: false` у checkout. Внешний ввод не интерполируется в shell: передаётся через окружение и валидируется. Не выполняйте PR-код через `pull_request_target` и не выдавайте production credentials runner для непроверенных веток.

Обязательные security checks: поиск секретов Gitleaks и аудит lockfile-зависимостей используемого стека. Подтверждённые исключения имеют причину, владельца и срок; широкие игноры запрещены. Dependabot обновляет Actions и зависимости через PR, без обхода ревью.

Доступ выдаётся минимально необходимый. Ключ поставки отличается от ключа для GitHub и разрешает только конкретное действие поставки. SSH host key проверяется заранее; `StrictHostKeyChecking=no` запрещён. Production pipeline имеет журнал, ограниченный доступ к окружению, проверку здоровья и откат.

Приватность нового репозитория проверяется чтением API после создания. Недоступность защиты на текущем тарифе сообщается явно; приватный репозиторий не публикуется как обход. Токен настройки не добавляется в репозиторий или CI. GitHub-side администрирование проводится только с разрешённым административным доступом.
