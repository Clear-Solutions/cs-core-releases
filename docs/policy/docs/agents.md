# Поддержка AI-агентов

`AGENTS.md` — единый источник правил проекта для Codex, Cursor, Claude Code и Google Antigravity.

| Клиент | Вход в правила |
| --- | --- |
| Codex | Корневой `AGENTS.md` |
| Cursor | `.cursor/rules/*.mdc`, `alwaysApply: true`, ссылка `@AGENTS.md` |
| Claude Code | Корневой `CLAUDE.md` с импортом `@AGENTS.md` |
| Google Antigravity | Корневой `AGENTS.md` и `.agents/rules/project.md` с `trigger: always_on` |

При создании любого нового репозитория добавьте все четыре входа. Скопируйте
`templates/CLAUDE.md` в корень и `templates/antigravity-rule.md` в
`.agents/rules/project.md`. Укажите реальные команды установки, проверок и доставки
в `AGENTS.md`. Проверяйте наличие файлов и ссылки на единый источник в CI.
Не копируйте полный набор правил в клиентские файлы: это приводит к расхождениям.

Личные инструкции `CLAUDE.local.md` и `.claude/settings.local.json` не коммитятся.
Правила агента не заменяют разрешения GitHub, защиту веток и CI. Этот набор файлов
не устанавливает клиенты, не подключает аккаунты и не выдаёт агентам разрешения.
После открытия проекта проверьте обнаружение инструкций в используемом клиенте.
Совместимость файлов проверена по документации; запуск всех четырёх клиентов
в каждом репозитории отдельно не проводился.

Официальная документация: [Claude Code](https://code.claude.com/docs/en/memory),
[Antigravity](https://www.antigravity.google/docs/rules/).

## Рабочий процесс

Порядок работы агента: прочитать инструкции и Git status; определить критерии; создать feature branch; реализовать изменение; выполнить релевантные проверки и визуальный осмотр; обновить контрактную документацию; открыть PR; указать фактические результаты и ограничения. Агенты не ставят approvals от имени людей и не обходят required checks. Разрешение «полный доступ» не отменяет установленный процесс PR.

Нельзя утверждать, что защита активна, repository создан или CD работает, опираясь только на подготовленные файлы. Состояние подтверждается GitHub API и фактическими runs/deployments. Недоступный connector/API не мешает подготовить локальное изменение, но является блокером администрирования GitHub.

При запросе нового проекта следуйте [процессу создания](project-bootstrap.md): самостоятельно выбирайте стек и зависимости, документируйте обоснование и источники, подключайте каталог/Delivery и подтверждайте проверки. Не просите пользователя выбрать каждую библиотеку и не считайте шаблон FastAPI обязательным.

Для подготовки среды нового участника используйте [промпт рабочего каталога](workspace-bootstrap.md). Он подключает источники правил и проверяет доступы, не создавая продукт и не выдавая права.

Повторяемые сценарии команды хранятся в [cs-core-skills](https://github.com/Clear-Solutions/cs-core-skills). Первый скилл `cs-workspace-setup` готовит каталог по этим стандартам; выберите и подключите его по инструкции Skills. Создание нового продукта не разрешает устанавливать всю библиотеку автоматически.
