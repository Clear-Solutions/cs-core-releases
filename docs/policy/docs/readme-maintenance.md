# Актуальность README

README описывает фактическое состояние, а не желаемый результат. Обновление
документации входит в готовность изменения, когда затронуты сведения для участника.

| Что изменилось | Где обновить |
| --- | --- |
| Назначение, функции, платформы, ограничения, установка/запуск | README проекта |
| Команды тестов, конфигурация, deployment, health/rollback | README и соответствующий документ проекта |
| Название/URL репозитория, роль, связи | README репозитория, каталог и архитектуру Hub, ссылки профиля |
| Общие правила, агентские входы, промпты/скиллы, подготовка участника | Standards, Skills/Hub по затронутому сценарию, README организации |
| Новый проект | README проекта и каталог Hub; профиль обновляется, если меняется общая навигация/схема |

Перед завершением проверьте локальные ссылки, существование удалённых репозиториев
и корректность команд подходящим способом. Для секретных production-сценариев
достаточно правдивого статуса и уже полученных свидетельств; не делайте выпуск
только ради README. Тестовые данные не подменяют реальные интеграции.

Копии промптов в профиле синхронизируются с каноническим источником и отмечают его
commit. Исторические policy snapshots и журналы завершённых этапов не переписываются:
новые правила принимаются отдельным pin/snapshot изменением.
Личные результаты диагностики, секреты и постоянно меняющиеся статусы задач
не публикуются в README; живое планирование остаётся в Issues/Delivery.

Если изменение не затрагивает README, не переписывайте его ради галочки:
зафиксируйте причину в PR. Отчёт агента перечисляет затронутую документацию
и конкретные непроверенные сведения. Недостаток доступа не разрешает заявлять,
что README другого репозитория уже обновлён.
