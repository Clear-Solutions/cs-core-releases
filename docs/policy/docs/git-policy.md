# GitHub и ревью

`main` — ветка проверенного состояния проекта. Ветки задач называются `feat/...`, `fix/...`, `chore/...` или `docs/...`. Все изменения проходят PR; применяется squash merge. Commit history не переписывается в общих ветках.

## Защита

Ruleset `Clear Solutions · main protection` активен для `refs/heads/main`: одно одобрение, code-owner review, сброс approvals при новых изменениях, отдельное одобрение последнего push, закрытые обсуждения, обязательные `checks`/`security`, актуальная база `main`, линейная история, запрет force push и удаления. `bypass_actors` пуст. Администратор может менять настройки GitHub; это полномочие не является обходом текущих правил и не должно использоваться для проталкивания PR.

Одно одобрение — от eligible пользователя, который не является автором PR. CODEOWNERS не требует автоматически одобрения от каждого указанного владельца: число обеспечивает ruleset. AI-анализ полезен как дополнительная проверка, но не заменяет одно человеческое ревью. PR от `elementary1997` может одобрить `light2217`, и наоборот; оба должны иметь право review/write.

Настройки сторонних правил не удаляются. Если существующие проверки строже, они сохраняются. Защиту включают сразу после первоначального импорта пустого репозитория; отсутствие доступного независимого ревьюера оставляет PR заблокированным, а не разрешает прямой push.

## Владельцы и права

В CODEOWNERS указываются реальные аккаунты/команды с доступом на запись. Production, workflows, инструкции агентов и настройки доступа требуют особенно внимательного review. Дополнительных участников не приглашайте без указания владельца. Для масштабирования используйте GitHub organization с командами maintainers и reviewers; владение личным репозиторием не переносите самовольно.

## Проверка фактического состояния

`tools/github_admin.py audit OWNER/REPO` читает права, приватность, правила и участников. `apply` записывает требуемые настройки и делает read-back. Файл JSON в Git, текст CONTRIBUTING или локальный hook не заменяют серверную защиту. Для приватных репозиториев нужен подходящий платный тариф; поддержка protected environments проверяется отдельно.

Изменения политики также проходят PR с одним approval. Не удаляйте защиту для срочного исправления: используйте обычный PR, проверку и откат последней стабильной версии через pipeline.
