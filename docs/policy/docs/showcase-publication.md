# Публикация проекта на витрине

Для каждого нового опубликованного проекта обязательны единое оформление превью
в стиле первых проектов, доступное интерактивное демо и проверка стандартов/UI.
Сценарий: [cs-showcase-publish](https://github.com/Clear-Solutions/cs-core-skills/blob/main/skills/delivery/cs-showcase-publish/README.md).
Код витрины: [cs-project-showcase](https://github.com/Clear-Solutions/cs-project-showcase).

Настоящий продукт с демонстрацией интерфейса не считается тестовым проектом.
Для desktop/CLI/API можно показать simulation сценария, явно помечая ограничения;
не переписывайте продукт в web только ради витрины. Реальные demo/installer/source
имеют раздельные безопасные ссылки, доступные предполагаемому посетителю.
Private репозиторий не раскрывается автоматически; не предлагайте private release
публичному посетителю как доступное скачивание.

Обновляйте существующий ID без дублей и потери данных. До публикации проверьте
функции/статус/платформы по коду, pinned policy, четыре agent entrypoints, lockfiles,
checks/security конкретного SHA, реальную CD, Hub/catalog/Delivery, русский текст,
скриншоты 320/390/768/1440 px, 200% zoom, клавиатуру и reduced motion.
Simulation, неподтверждённая платформа и невозможность private protection на Free
отмечаются честно; отсутствие evidence не становится успешной проверкой.
Публикация выполняется только в рамках пользовательского запроса и доступов;
не меняет права, брендинг продукта или инфраструктуру как побочный эффект.
